# PRD: 싱글 배틀과 포켓몬식 팀 토너먼트 배틀

## 1. 목적

Damagochi는 두 가지 P2P 배틀 모드를 제공한다.

| 모드 | 참가자 | 승리 조건 |
|---|---|---|
| 싱글 배틀 | 선택한 살아 있는 펫 1마리 | 상대 펫 HP를 0으로 만든다 |
| 토너먼트 배틀 | 각 플레이어의 살아 있는 펫 전원(최대 4마리) | 상대 팀의 모든 펫을 쓰러뜨린다 |

토너먼트 배틀은 4마리끼리의 단발성 대진표가 아니다. 포켓몬의 팀 대전처럼 각 팀이 슬롯 순서로 펫을 내보내며, 현재 펫이 쓰러지면 다음 살아 있는 펫이 이어서 싸운다. 마지막 펫까지 쓰러진 팀이 패배한다.

## 2. 사용자 경험

### 공통

- 배틀 화면 상단에서 `싱글`과 `토너먼트`를 고른다.
- 매칭 전에 모드를 변경할 수 있고, 연결 또는 전투가 시작된 뒤에는 바꿀 수 없다.
- 배틀에 사용되는 레벨은 `min(max(level, 0), 50)`이며 저장 레벨은 바꾸지 않는다.
- 프로필을 보낼 때 현재 장비의 head/hand/effect 외형과 보정만 스냅샷으로 보낸다.

### 싱글 배틀

- 현재 선택한 슬롯의 alive 펫 1마리만 참가한다.
- 1마리라도 battle-eligible이면 시작할 수 있다.
- 기존 P2P 1:1 UX와 보상 규칙을 유지한다.

### 토너먼트 배틀

- 양쪽 모두 alive 펫이 2마리 이상 있어야 매칭을 시작한다.
- 슬롯 1→4 순서로 모든 alive 펫을 팀에 넣는다. egg/dead 펫은 제외하며 슬롯 순서는 유지한다.
- 한 펫이 KO되면 그 펫은 전투에서 제외되고, 같은 팀의 다음 살아 있는 펫이 즉시 교체 투입된다.
- 교체된 펫은 전투 시작 시 스냅샷으로 잡은 최대 HP로 시작한다. 살아남은 펫은 현재 HP를 유지한 채 다음 상대와 싸운다.
- 양 팀 모두 마지막 펫이 쓰러질 때까지 반복한다. 한 팀의 살아 있는 펫이 0이면 배틀이 종료된다.
- 전투 화면은 양 팀의 2×2 펫 목록, 현재 출전 펫, KO 상태, 현재 HP를 함께 표시한다.
- 모드 안내는 “내 팀 전원 출전 · 쓰러질 때까지 순차 대결”로 명확히 표시한다.

## 3. 데이터 및 네트워크 모델

### `BattleMode`

```swift
enum BattleMode: String, Codable, Sendable {
    case single
    case team
}
```

### `BattleTeamProfile`

```swift
struct BattleTeamProfile: Codable, Sendable, Identifiable {
    let id: String
    let members: [BattleProfile] // 1...4, 슬롯 순서
}
```

- `BattleProfile`은 기존처럼 전투 시작 시점의 능력치, 유효 배틀 레벨, 외형, 장비 보정을 포함한다.
- 인벤토리 전체나 저장 상태는 전송하지 않는다.
- 팀 프로필은 최대 4명으로 제한한다.
- 알 수 없는 장비 ID, 외형 없는 구버전 프로필은 기존 기본 스프라이트 폴백을 사용한다.

### 메시지 호환성

- 싱글 배틀은 기존 `.profile(BattleProfile)` 메시지를 유지한다.
- 토너먼트 배틀은 `.teamProfile(BattleTeamProfile)` 메시지를 사용한다.
- 같은 모드끼리만 매치해야 한다. 구버전 클라이언트가 팀 메시지를 해석하지 못하면 연결 시간 초과 후 안전하게 배틀 목록으로 복귀한다.
- 배틀 중 장비/레벨/인벤토리가 바뀌어도 이미 전송된 프로필은 변경되지 않는다.

## 4. Core 전투 규칙

`TeamBattleState`는 UI 및 네트워크와 독립적인 Core 상태다.

```swift
struct TeamBattleState {
    var myTeam: [BattleProfile]
    var opponentTeam: [BattleProfile]
    private(set) var myActiveIndex: Int
    private(set) var opponentActiveIndex: Int
    private(set) var activeBattle: BattleState
    private(set) var status: TeamBattleStatus // ongoing, victory, defeat
}
```

1. 현재 출전하는 두 `BattleProfile`로 기존 `BattleEngine.resolveTurn`을 호출한다.
2. 승자는 갱신된 HP를 유지한다.
3. 패배자는 HP 0으로 고정하고 팀의 다음 슬롯을 찾는다.
4. 다음 슬롯이 있으면 새 `BattleState`로 다음 대결을 시작한다.
5. 다음 슬롯이 없으면 해당 팀이 패배한다.

다음 펫 선택은 랜덤이 아니라 슬롯 순서상 뒤에 있는 첫 alive 펫이다. 전투 중 부활 또는 중간 슬롯 재배치는 지원하지 않는다.

## 5. 펫별 정보와 장비 UX

### 설정(맨 왼쪽) 화면

- 슬롯 4개를 2×2 카드로 항상 표시한다.
- 각 카드에는 이름, 성장 단계, 레벨, HP, XP, MBTI, ATK/INT/DEF/SPD를 표시한다.
- 카드를 누르면 선택 펫과 상세 정보가 같은 슬롯으로 바뀐다.
- 능력치는 `BattleProfile.from`으로 계산하므로 레벨 50 상한, rarity, 해당 펫의 장비 보정이 반영된다.

### 인벤토리/장비 화면

- 화면 상단에 네 펫의 장비 요약 카드를 2×2로 표시한다.
- 카드에는 장착 수(최대 3), 해당 펫 인벤토리 수, ATK/DEF를 표시한다.
- 카드를 누르면 그 펫의 인벤토리와 장착 장비를 조작한다.
- 장비와 인벤토리는 슬롯별 `PetState`에 저장되므로 다른 펫에게 장비나 능력치가 섞여 보이면 안 된다.

### 메뉴바 팝오버

- 2×2 펫 카드에서 각 펫의 레벨뿐 아니라 ATK/DEF/SPD 요약을 표시한다.
- 선택한 카드가 앱 전체의 선택 펫과 일치한다.

## 6. 보상

- 싱글 배틀 보상은 현재 선택 펫 기준의 기존 동작을 유지한다.
- 토너먼트 배틀의 XP 보상은 기존 `awardSharedXP`를 사용하여 모든 egg/alive 슬롯에 결정적으로 균등 분배한다. dead 펫은 제외한다.
- 장비 드롭이 있다면 최종 승리 시점에 살아남은 마지막 내 펫의 인벤토리에 지급한다. 해당 펫을 찾을 수 없으면 선택 펫으로 안전하게 폴백한다.
- 패배 또는 포기에는 장비 드롭이 없다.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| alive 펫이 0~1마리 | 토너먼트 시작을 막고 필요 인원을 안내한다 |
| egg/dead 슬롯 | 팀 목록에서 제외하고 UI에 사유를 표시한다 |
| 상대 팀이 1명 이하 | 팀 매치 시작을 거부하고 연결을 정리한다 |
| 진행 중 장비 변경 | 이미 생성된 팀 프로필에는 반영하지 않는다 |
| 알 수 없는 장비/스프라이트 | 기본 외형으로 폴백한다 |
| 한 턴에 양쪽 KO | 기존 `BattleEngine`의 결과 규칙을 따른 뒤 팀 상태를 갱신한다 |
| 연결 종료/포기 | 현재 팀전을 종료하고 패배 처리한다 |

## 8. 테스트와 완료 기준

Core 단위 테스트:

- 2~4명 팀의 프로필 제한 및 Codable 왕복
- 첫 상대 KO 뒤 두 번째 상대가 슬롯 순서로 교체되는지
- 살아남은 펫 HP가 다음 전투에서도 유지되는지
- 마지막 펫이 KO되기 전에는 팀전이 끝나지 않는지
- 마지막 펫 KO 시에만 승패가 확정되는지
- 싱글 모드와 기존 레벨 50/장비 외형 동작이 회귀하지 않는지

UI 수동 QA:

- 메인 윈도우와 메뉴바 팝오버의 네 펫 능력치 카드
- 인벤토리에서 슬롯 전환 시 장비/인벤토리 격리
- 싱글/토너먼트 전환, 2~4마리 팀, egg/dead 혼합, 장비 착용
- 전투 중 KO 교체와 각 방향 스프라이트, Reduce Motion

완료 조건은 `make build`, 전체 `swift test`, 팀전 Core 테스트, 그리고 P2P 두 인스턴스 수동 대전 확인이다.
